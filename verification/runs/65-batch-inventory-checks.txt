Run 65: batch inventory checks in the filled-group checkers and the manifest
=============================================================================
Date: 2026-08-29

Scope
-----

Before this run, each filled-group checker validated every certificate it
was given individually — format, input digest, case index and slug against
the hash-bound presentation, every derivation record, every identity root —
but neither driver made any batch-level assertion.  Supplying one valid
certificate eight times satisfied both drivers (the Ruby driver's
--expected-count only counts files).  The released certificates were and are
correct — eight distinct files covering case indices 0..7 — but the paper's
statement that a replay verifies exactly the four n=0 sign pairs and the
four n=1 controls relied on the manifest's file list, not on anything the
drivers checked.  An external reviewer demonstrated the duplicated-batch
acceptance on 2026-08-29.  This run closes it.

Changes
-------

verify_kbmag_certificate.py
  * Per-certificate verification is now verify_certificate(); main() collects
    (path, case index, slug) for the batch and calls check_inventory().
  * check_inventory() always rejects a batch that verifies any case index or
    slug twice.  With --full-inventory it further requires: indices exactly
    0..len(paper_fillings)-1; each file named <slug>.json.gz; source with 4
    generators, 95 complement relators, 8 fillings, 2 filling relators per
    case; and the batch's slugs equal to the input's filling inventory.
  * --negative-controls proves that a duplicated batch and a corrupted
    identity root are rejected.

verify_certificates.rb
  * Same check_inventory, same rules.  --[no-]full-inventory; on by default
    when no certificate paths and no --input are given (the documented
    eight-certificate invocation), off for the single-certificate
    --input/--expected-count 1 replays of runs 59-62.
  * --negative-controls gains a fourth control: a duplicated batch is
    rejected.

make_proof_manifest.py
  * check_inventory() refuses to write or --check a manifest unless
    proof_certificates/ holds exactly one file per filling of
    r_presentations.json, named by its case slug.

Because the manifest hashes both checkers, proof_certificates/manifest.json
is regenerated (24 files; the eight certificates and every other hashed
file are byte-identical to v1.5).  Because the downstream chain binds the
manifest as evidence, downstream_chain_certificate.json is regenerated; its
mathematical content (25 external, 3 certificate, 15 computed, 16 step
items) is unchanged.
